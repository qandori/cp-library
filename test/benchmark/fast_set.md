# Predecessor Set（64 分木）

## 実装

整数集合は `components/predecessor_set.hpp` の `PredecessorSet` に統一しました。区間ソート木も同じ部品を使います。以下は旧称 Fast Set で行った測定記録で、保存済みのソースハッシュと結果は変更していません。

- 64 bit 語を階層化し、全階層を 1 本の配列に配置。
- 挿入・削除では語の空／非空が変化した部分だけ上へ反映。
- 前後の探索にはシフトと `countr_zero`／`countl_zero` を使用。空集合は即座に返す。
- 0/1 列は 64 文字ずつまとめて変換し、上位階層と要素数を構築。
- x86_64 の長い 0/1 列は実行時判定で AVX2 を使用。その他は整数演算で変換。
- 範囲列挙は語ごとに探索し、その語の要素をまとめて取り出す。

範囲長は `INT_MAX` までで、固定の最大サイズや利用者のマクロには依存しません。Mac ARM には AVX2 のコードを含めません。

## 測定条件

- WSL2 Ubuntu、Intel Core i7-13700F、Linux x86_64、GCC 15.2.0。
- `-std=c++23 -O2 -DEVAL -DONLINE_JUDGE -march=native -ftrivial-auto-var-init=zero`。assert は有効。
- CPU 2 に固定。各条件でウォームアップ 1 回と測定 7 回を行い、中央値を掲載。
- 乱数 seed と実行順 seed は 403023。比較対象の順番は各試行でシャッフル。
- コンパイルをすべて終えてから測定。実行中に他のテストやドキュメント生成を行わない。
- 実行ファイル・入力・出力は Linux の `/tmp`。全体時間は通常ファイルを標準入出力に接続した新規プロセスで測り、起動・構築・入出力・終了を含む。checker とハッシュ計算は計時外。
- 従来版はコミット `b584f748d67d38faf22229cb2c971ccd98ba7d6e` の `PredecessorSet`。同じ入出力で初期文字列を逐次 `insert` する。
- 「整数構築」は現実装の明示的 AVX2 分岐だけを無効化した版。`-march=native` によるコンパイラの自動ベクトル化は許可している。

[environment.json](results/fast_set/environment.json) に環境・ソースのハッシュ、[results.json](results/fast_set/results.json) に全試行・出力のハッシュを保存しています。Library Checker のサーバー環境で測定・提出した結果ではありません。

## 集合部分

`n=10,000,000`、`q=1,000,000`。文字列・操作の生成と入出力を計時から除き、構築と操作列を別に測定しています。ランダム／全要素ありは 5 種類の操作を一様に生成し、空／16 要素は存在判定・前後探索だけを生成します。各版のチェックサムと最終要素数を照合しています。単位は ms。

| 条件 | 従来の構築 | 現在の構築 | 整数構築 | 従来の操作 | 現在の操作 | 整数構築版の操作 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ランダム | 32.992 | 1.039 | 1.335 | 7.655 | 7.496 | 7.546 |
| 全要素あり | 14.411 | 0.891 | 1.305 | 5.720 | 5.701 | 5.665 |
| 空集合・探索のみ | 2.345 | 0.905 | 1.145 | 6.574 | 4.564 | 4.529 |
| 16 要素・探索のみ | 2.209 | 0.920 | 1.144 | 8.043 | 8.231 | 8.029 |

改善の中心は文字列からの一括構築です。空集合の探索も短縮しました。16 要素の場合の操作時間は従来版より約 2% 長く、すべての条件で探索が速くなったとはいえません。

`n=10,000,000` の動的確保量は従来 1,269,952 bytes、現在 1,269,856 bytes。オブジェクト自体は従来 32 bytes、現在 88 bytes です。現在は階層情報をオブジェクト内に持つため、この部分は増えています。

## 利用先への影響

`SortableSegtree` のソースと入出力を同じにし、内部の `PredecessorSet` だけを切り替えました。公式 checker で確認しています。単位は ms。

| ケース | 従来の部品 | 現在の部品 |
| --- | ---: | ---: |
| `max_random_00` | 163.125 | 167.951 |
| `many_1_query_00` | 80.911 | 81.185 |
| `many_2_query_00` | 187.788 | 185.546 |

最大ランダムケースは約 3% 長く、他の 2 ケースは同程度です。この利用先で一律の高速化は確認できていません。

## 検証と再現

GCC 15.2・13.4 と Clang 21 で単独 include・単体テストを確認し、Clang ASan/UBSan、`NDEBUG` も検証しています。`FastSet` は公式 22 ケース、依存する区間ソート木は公式 23 ケースを GCC・Clang で通過しました。結合した `FastSet` の提出コードも Clang の `NDEBUG` で 22 ケースを確認しています。

単体テストには 64 の累乗付近、空・全体集合、ランダム更新、範囲列挙、AVX2／整数変換の照合、自己参照からの再構築、コピー・ムーブ、`INT_MAX` の範囲長を含みます。

```sh

python3 test/benchmark/fast_set.py \
  --references .verify-helper/cache/fast-set-reference \
  --official ~/.cache/online-judge-tools/library-checker-problems/data_structure/predecessor_problem \
  --output test/benchmark/results/fast_set --cpu 2 --trials 7
```

参考提出の取得先や API は `fast_set_reference.py --help` で確認できます。測定には GCC 15 と、生成済みの公式入力・出力・checker が必要です。
