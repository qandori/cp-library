# Slope Trick のベンチマーク

2026-10-15、macOS arm64 / GCC 15.2、`-std=c++23 -O2 -DNDEBUG`。乱数 seed 713、各候補を順序を変えて 5 回ずつ実行した中央値です。単位は ms、マージ木だけ 65,536 個、その他は 300,000 回です。すべての候補で checksum が一致しています。

```sh
g++ -std=c++23 -O2 -DNDEBUG -I . test/benchmark/slope_trick.cpp -o /tmp/slope-bench
/tmp/slope-bench library random 300000 713
/tmp/slope-bench standard random 300000 713
```

引数は実装、入力の種類、要素数、seed です。

`standard` は `std::priority_queue` を 2 個使い、絶対値追加を左右の折れ線追加に分け、マージ元を順に pop する実装です。`standard_fused` は絶対値追加を統合し、マージ元の内部配列を走査します。`binary`・`quaternary`・`octary`・`hexadecary` は根の置換を一度の sift-down で済ませる候補です。`library` は採用した実装で、消費したマージ元の領域も解放します。

採用した工夫は、根の置換と追加・削除の統合、絶対値追加の直接処理、左右の遅延移動、小さい関数からのマージ、マージ元の配列走査、確保領域を残す片側の消去です。`eval` も配列を走査し、関数のコピーや破壊を行いません。

比較した候補は以下です。

- 二分・四分・八分・十六分ヒープ。四分以上はマージで有利な場合がありますが、単調入力や累積最小値の DP を含めて二分を選びました。
- `direct_binary`・`direct_four` は子の選択を分岐で明示した候補です。通常のループより遅くなるケースが多く、採用していません。
- `floyd_binary`・`floyd_four` は下まで降りてから戻す候補です。別の同条件比較では、累積最小値の DP が二分の通常処理 11.59 ms に対して 14.46 ms になりました。
- `batch64`・`batch256`・`batch1024`・`batch256_four` は近い大きさのマージを `nth_element` と heapify で行う候補です。262,144 個のマージ木では、二分の配列走査 79.76 ms に対して `batch256` が 104.96 ms、四分の配列走査 69.37 ms に対して `batch256_four` が 92.79 ms でした。追加領域も必要なため採用していません。
- `release_binary`・`release_four` ではマージ元の確保領域の解放も比較しました。採用実装では、消費済みの関数を木の各頂点に残しても不要な領域を保持し続けないようにしています。

入力の種類は `random`・`increasing`・`decreasing`・`duplicates`・`sliding`・`prefix`・`hinges`・`merge_balanced`・`merge_small` です。
