# 合成の valuation による打ち切り

**判定: 採用保留。** 特化入力の高速化と正当性は確認しましたが、よく使われる valuation 1 の native ケースで6組中5組の低下があり、自動マージの対象にしません。同じ版の繰り返し計測や閾値調整は行わず、今後の再検討には別の構造的な説明が必要です。

## 変更

内側の多項式の最初の非零次数を v、出力の長さを n とすると、外側の i 次項は i v >= n のとき寄与しません。既存の単項式処理の後で外側を ceil(n/v) 項に切り詰め、もう一度末尾の零を除きます。整数の切り上げは (n-1)/v+1 とし、公開 API、返り値の長さ、係数型、単項式処理は変更しません。v=1 では追加の除算や切り詰めを行いません。

主な効果は、残る外側が8項以下になった場合に既存の Horner 処理を選べることです。NTT のアルゴリズム、プランの寿命、共有キャッシュは変更しません。すべての入力が速くなる変更ではありません。

## 参考

[Library Checker の提出409336](https://judge.yosupo.jp/submission/409336)の一般的な合成と Transform の使い方を調査しました。この打ち切り自体は次数から導いたもので、提出コードの実行やコピーではありません。ジャッジ上の実行時間は以下の比較に使っていません。

## 比較条件

2026-10-17、Linux x86_64、Intel Xeon Platinum 8573C、GCC 14.2.0、C++23。generic は -O2 -DNDEBUG、native はさらに -march=native。ヘッダー既存の GCC O3 指定は両版に残しています。CPU 0 に固定した共有クラウド環境であり、AtCoder の実機計測ではありません。

基準は117fda44639532534bc91fb02517a1cba09ee738の compose.hpp。関数名だけを変えて同一実行ファイルに入れ、再帰的なローカル依存4ヘッダーの完全一致を確認します。28ケース、各6組、先行順を3組ずつ入れ替え、2設定で計336組です。各版各組の実測プロセス CPU 時間が0.2秒以上になるまで測定します。計測前に出力全体の一致を確認し、各呼び出しの全係数チェックサム計算は両版の計測内に含めています。入力は固定乱数です。

速度比は基準/変更版で、大きいほど速い値です。組ごとの比の中央値と、各版の時間中央値同士の比は別々に示します。全56ケースを掲載し、不利な組も残しました。v1 の通常の合成、単項式、すでに短い外側、境界サイズを対照に含めています。

## 結果と制約

大きな valuation で外側が8項以下になる dense 入力では、generic の代表8ケースは1.42–8.03倍、native は1.50–8.42倍でした。次数32768、v8192 は18.414→2.235 ms、native は18.930→2.248 msです。切り詰めた外側がすべて零になる専用ケースは70.39倍と67.72倍で、通常の dense 合成の速度としては扱いません。

不利な結果もあります。native の n64/v4 は0.928倍（16.582→17.877 µs）、n4096/v1 は0.944倍（1.478→1.575 ms、6組中5組で遅い）、n129/v16 は0.960倍（51.424→54.843 µs）でした。generic n129/v16 は組ごとの比で0.958倍ですが時間中央値の比は1.010倍です。native n4096/v256 の個別比には約0.03、0.43、n32768/v1 に約0.05があり、分散を隠していません。native n65/v9 は中央値1.146倍ですが6組中3組で遅く、この境界の安定した改善は主張しません。変更のない経路にも不利な結果があり、全入力での非退行は保証しません。

先行する42ケース・各3組の探索計測も破棄していません。そこで native n64/v1 は0.221倍、n256/v16 は0.096倍、n64/v2 は0.765倍、generic 単項式対照は0.901倍でした。最終計測はあらかじめ固定した全ケース・均等順序で行い、都合のよいケースだけを再測定したものではありません。探索と最終の間で production は変えていません。最終後の追加測定や閾値調整も行っていません。

表の時間は CPU µs/呼び出しの中央値です。kind は dense、monomial（内側が単項式）、zero-prefix（残る外側がすべて零）、short-outer（外側8項）の4種類です。

## 正当性と再現

独立した冪和オラクルを使い、標準 Mint と通常の剰余表現の PlainMint、空・定数・零の多項式、単項式、打ち切り後に零になる外側、7/8/9項と次数境界、既定の次数、入力不変性と入力の共有を確認しました。独立オラクルの GCC O2 と ASan/UBSan、新しい compose_valuation 単体テストと既存 fps_algorithms 単体テストが成功しています。サニタイザーでは実行環境の制約で LeakSanitizer のみ無効です。Mac の速度改善は主張しません。
