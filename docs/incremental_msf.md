---
title: 辺追加に対応する最小全域森
documentation_of: //graph/incremental_msf.hpp
library_category: graph/spanning_tree
---

重み付き無向グラフに辺を追加しながら、最小全域森とその重みの総和を管理します。最小全域森は、各連結成分を木でつなぐ辺の選び方のうち、重みの総和が最小のものです。グラフ全体が連結なら最小全域木になります。

```cpp
#include "lib/graph/incremental_msf.hpp"
#include <cassert>

int main() {
	IncrementalMSF<> graph(4);
	assert(graph.add_edge(0, 1, 5) == -1);
	assert(graph.add_edge(1, 2, 5) == -1);
	assert(graph.add_edge(0, 2, 4) == 1);
	assert(graph.total_cost() == 9 && graph.component_count() == 2);
	assert(graph.add_edge(0, 1, 5) == 3);
	assert(graph.add_edge(2, 3, -2) == -1);
	assert(graph.connected() && graph.total_cost() == 7);
	assert(graph.edge_count() == 5 && graph.forest_edge_count() == 3);

	auto maximum = graph.path_max(0, 2);
	assert(maximum && maximum->cost == 4 && maximum->id == 2);
	assert(!graph.path_max(1, 1));
	assert(graph.same(0, 3) && graph.component_size(1) == 4);
}
```

辺には、追加した順に 0 始まりの番号を付けます。`add_edge` の返り値は、追加後の最小全域森から**除外する辺の番号**です。

- 異なる連結成分をつなぐ場合、新しい辺を採用して `-1` を返します。
- 既存の経路にある辺を新しい辺と入れ替える場合、取り除いた古い辺の番号を返します。
- 新しい辺を採用しない場合、新しい辺自身の番号を返します。自己ループもこの扱いです。

同じ重みでは、番号が小さい辺を優先します。例の辺 0・1 はともに重み 5 なので、辺 2 の追加では番号が大きい辺 1 を除きます。自己ループや不採用の辺も追加回数に含め、以降の辺番号を進めます。

表の $$N$$ は頂点数、$$M$$ は `clear()` 後の辺追加回数です。空間の列は返り値を含む追加空間で、整数の演算・比較・コピーを定数時間とします。

| 操作・型 | 内容・返り値 | 時間計算量 | 追加空間 |
| --- | --- | --- | --- |
| `IncrementalMSF<Cost,Sum>(n = 0)` | `n` 頂点、辺なしの森を構築。既定は `Cost = std::int64_t`、`Sum = __int128_t` | $$O(N)$$ | $$O(N)$$ |
| `size()` | 頂点数を `int` で返す | $$O(1)$$ | $$O(1)$$ |
| `edge_count()` | 自己ループ・不採用の辺も含む追加回数を `int` で返す | $$O(1)$$ | $$O(1)$$ |
| `forest_edge_count()` | 現在の最小全域森の辺数を `int` で返す | $$O(1)$$ | $$O(1)$$ |
| `component_count()` | 孤立点を含む連結成分数を `int` で返す | $$O(1)$$ | $$O(1)$$ |
| `connected()` | グラフ全体が連結かを `bool` で返す。0 頂点でも `true` | $$O(1)$$ | $$O(1)$$ |
| `total_cost()` | 最小全域森の辺の重みの総和を `Sum` で返す | $$O(1)$$ | $$O(1)$$ |
| `add_edge(u,v,cost)` | 無向辺を追加し、除外する辺番号を `int` で返す。除外なしなら `-1` | 償却 $$O(\log N)$$ | $$O(1)$$ |
| `same(u,v)` | 同じ連結成分に属するかを `bool` で返す | 償却 $$O(\log N)$$ | $$O(1)$$ |
| `component_size(v)` | 頂点 `v` が属する連結成分の頂点数を `int` で返す | 償却 $$O(\log N)$$ | $$O(1)$$ |
| `path_max(u,v)` | 森の `u` から `v` への経路で、重みが最大の辺を `optional<Edge>` で返す。同じ重みなら番号が大きい辺 | 償却 $$O(\log N)$$ | $$O(1)$$ |
| `forest_edges()` | 現在採用している辺を `vector<Edge>` で返す。順序は未規定 | $$O(N)$$ | $$O(N)$$ |
| `clear()` | 全ての辺を消し、辺番号を 0 から再開する。頂点数は維持 | $$O(N)$$ | $$O(1)$$ |
| `Edge` | 辺の重み `Cost cost` と辺番号 `int id` を持つ | —（型） | —（型） |
| `cost_type` / `sum_type` | それぞれ `Cost`・`Sum` の別名 | —（型） | —（型） |

頂点番号は `[0,N)` です。負の重み、重複する重み、多重辺、自己ループ、孤立点に対応します。採用辺数は常に `forest_edge_count() == size() - component_count()` です。空のグラフは重みの総和 0、連結成分数 0、採用辺 0 本で、問い合わせに使える頂点はありません。

`path_max(u,v)` は `u == v`、または非連結の場合に `std::nullopt` を返します。両者を区別したい場合は `same(u,v)` で調べます。この操作が返すのは、現在の最小全域森の経路にある辺です。異なる連結な 2 頂点では、この最大重みは、元のグラフで 2 頂点を結ぶ経路を選んだときの「経路内の最大辺重み」の最小値でもあります。

`forest_edges()` の結果は、その時点の辺番号と重みをコピーした配列です。後の辺追加や `clear()` によって書き換わりません。各辺の両端が必要なら、入力した辺を別の配列に保存し、`id` で参照してください。このライブラリは不採用の辺や取り除いた辺の一覧を保持しません。

任意の辺の削除や重み変更はできません。取り除いた辺は、今後の辺追加で再び採用する必要がないため、保持しなくても最小全域森を更新できます。辺の追加順が全て分かっていて、途中の答えが不要なら [Kruskal](kruskal.md) も使えます。

`Cost` は `bool` を除く 64 bit 以下の標準整数型で、符号付き・符号なしのどちらも使えます。最小値・最大値を含め、`Cost` の全ての値を辺の重みに使えます。`Sum` は 128 bit 以下の符号付き整数型で、`Cost` の全ての値を表せる型にします。既定の `__int128_t` なら、有効な頂点数と 64 bit の重みで作る森の総和を表現できます。より小さい `Sum` を指定する場合は、各追加後の総和が `Sum` に収まる必要があります。既定の総和は [FastOutput](fast_io.md) で出力できます。

頂点数は `0 <= N < INT_MAX`、追加回数は `M <= INT_MAX` にします。`clear()` は採用辺・総和・追加回数を初期化し、全頂点を孤立点に戻します。それまでの辺番号は、新しい森に対して使えません。

頂点数を $$N$$ とすると、構築は $$O(N)$$ 時間・空間です。`add_edge`・`same`・`component_size`・`path_max` は償却 $$O(\log N)$$、1 回の最悪時間は $$O(N)$$ です。「償却」は、一連の操作にかかる合計時間から求めた、1 回あたりの計算量を表します。頂点が 0 個・1 個の場合に可能な操作は定数時間で扱います。追加回数 $$M$$ によらず、保持空間は $$O(N)$$ です。共有する前計算表や、呼び出しをまたいで増え続ける履歴はありません。

コピー構築は $$O(N)$$ 時間・空間で、コピー後は独立して変更できます。コピー代入には代入元と代入先の頂点数の和に比例する時間、コピー元の頂点数に比例する追加空間以内を使い、確保済みの領域が残る場合があります。その場合の保持空間は確保済みの容量に比例します。`clear()` も確保済みの容量を減らしません。移動構築は $$O(1)$$ 時間・追加空間、移動代入には代入先の旧領域を解放する時間が加わり、追加空間は $$O(1)$$ です。移動元は頂点数・辺数・連結成分数が 0 の空の状態になります。

参考: Ding・Gu・Sun, [New Algorithms for Incremental Minimum Spanning Trees and Temporal Graph Applications](https://arxiv.org/abs/2504.04619)。
