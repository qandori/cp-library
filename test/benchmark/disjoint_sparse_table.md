# Disjoint Sparse Table のベンチマーク

リポジトリのルートで実行します。

```sh
g++ -std=c++23 -O2 -DNDEBUG -I . test/benchmark/disjoint_sparse_table.cpp -o /tmp/disjoint-sparse-table-bench
/tmp/disjoint-sparse-table-bench 200000 1000000 0 0 0
/tmp/disjoint-sparse-table-bench 200000 1000000 0 0 1
```

引数は要素数、クエリ数、演算（0 が 64bit 整数の min、1 が mod 998244353 のアフィン変換の合成）、短区間を使うか（1 なら長さ 1〜8）、比較対象を使うか（1 なら通常実装）です。固定の乱数種で作り、クエリを一度実行してから時間を測ります。

2026-10-15、macOS arm64、GCC 15.2 / Apple Clang 21、上記の条件で 5 回交互に実行した中央値。比較対象はテンプレートで演算を指定し、全行を元配列で初期化する通常の Disjoint Sparse Table です。いずれも関数オブジェクトの動的な呼び出しは使いません。時間の単位は ms です。

| コンパイラ | 演算 | 通常の構築 | 今回の構築 | 通常の 100 万クエリ | 今回の 100 万クエリ |
| --- | --- | ---: | ---: | ---: | ---: |
| GCC | min | 3.948 | 3.524 | 1.946 | 1.970 |
| GCC | 関数合成 | 16.801 | 15.779 | 5.613 | 5.625 |
| Clang | min | 4.499 | 3.508 | 1.936 | 1.950 |
| Clang | 関数合成 | 15.822 | 11.770 | 4.553 | 4.559 |

50 万要素と短い区間でも比較し、全ケースで checksum が一致しました。問い合わせ速度の差は小さく、コンパイラと入力によって変わります。主な改善は構築時の初期化・コピーの削減です。
