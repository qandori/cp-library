[辺追加に対応する最小全域森](incremental_msf.md)の内部部品です。通常は `graph/incremental_msf.hpp` の `IncrementalMSF` を使います。

`am_tree_detail::Tree<Key,less>` は、辺の追加と、2 頂点間の経路にある最大の辺の取得を扱います。各辺のラベル `Key` に重みと元の辺番号を持たせ、`less(a,b)` で重み、同じ重みなら辺番号の順に比較します。ラベルは互いに区別でき、比較結果は途中で変化しないようにします。`less(a,a)` は `false`、異なるラベルはどちらか一方が小さく、`a < b` かつ `b < c` なら `a < c` となる比較が必要です。辺番号は追加順に増やしますが、重みは任意の順序で構いません。

内部の親子関係は元の辺の両端を表しません。保持するラベルから、元の最小全域森の辺を取得できます。任意の辺の削除や、追加済みの辺の重みの変更には対応しません。

頂点数を $$n$$、`for_each` の関数の 1 回あたりの時間を $$T_f$$ とします。頂点番号は `[0,n)`、`0 <= n < INT_MAX` とします。表の空間は返り値を含む追加空間です。

| 操作 | 内容・条件 | 時間計算量 | 追加空間 |
| --- | --- | --- | --- |
| `Tree(n = 0)` | `n` 頂点、辺なしで構築 | $$O(n)$$ | $$O(n)$$ |
| `size()` / `component_count()` | 頂点数／連結成分数を `int` で返す | $$O(1)$$ | $$O(1)$$ |
| `clear()` | 頂点数を保って全辺を消す | $$O(n)$$ | $$O(1)$$ |
| `insert(u,v,key)` | 相異なる有効な頂点間に辺を追加。除かれた辺のラベルを `optional<Key>` で返す。新しい辺自身を採用しなければ `key`、異なる成分を結んだなら `nullopt` | 償却 $$O(\log n)$$ | $$O(1)$$ |
| `path_max(u,v)` | 元の最小全域森の経路で最大のラベルを `optional<Key>` で返す。同じ頂点、または非連結なら `nullopt` | 償却 $$O(\log n)$$ | $$O(1)$$ |
| `component_size(v)` | 有効な頂点 `v` の連結成分の頂点数を `int` で返す | 償却 $$O(\log n)$$ | $$O(1)$$ |
| `for_each(f)` | 採用中の各ラベルについて `f(key)` を 1 回ずつ呼ぶ。順序は未規定 | $$O(n+(n-c)T_f)$$ | 関数の作業領域を除き $$O(1)$$ |

$$c$$ は連結成分数で、採用中の辺数は $$n-c$$ です。`for_each` は `const` で呼べますが、実行中の関数から同じ木を変更しないでください。`Key` の既定構築・コピー・代入・交換・破棄、`less` の比較と関数オブジェクトのコピーを定数時間とします。

操作の「償却」は、一連の操作の合計時間から求めた 1 回あたりの計算量です。経路を調べる操作と辺の追加は、1 回だけなら最悪 $$O(n)$$ 時間かかります。再帰や操作ごとの作業配列は使いません。空の構築・走査・消去にも定数時間かかります。

通常の構築後の保持領域は $$O(n)$$ です。辺を追加しても領域を増やさず、過去に追加した辺数に比例する履歴は保持しません。確保済みのノード容量を $$C$$ とすると、コピー代入後なども含む実際の保持空間は $$O(C)$$ です。`clear` は容量を減らしません。共有表や前計算の保持はありません。

コピー構築は $$O(n)$$ 時間・空間で、コピー後の変更は独立です。コピー代入は代入前後の頂点数の和に比例する時間を使い、確保済み容量を保持する場合があります。移動構築は $$O(1)$$ 時間・追加空間、移動代入では代入先の旧領域の解放が加わります。移動元は 0 頂点の空の木になります。移動元の `clear` で、番兵 1 個分の領域を確保する場合があります。

参考: Ding・Gu・Sun, [New Algorithms for Incremental Minimum Spanning Trees and Temporal Graph Applications](https://arxiv.org/html/2504.04619v2), §5。
